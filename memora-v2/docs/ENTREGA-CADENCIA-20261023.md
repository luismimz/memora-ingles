# Aplicar cuando las palabras están preparadas

Entrega incremental sobre 989e584. No activa borradores ni incorpora contenido nuevo.

El recorrido sitúa una aplicación gramatical al aparecer su preparación léxica, incluso en un catálogo de una sola misión. El acceso continúa exigiendo un acierto previo en cada palabra requerida: aparición en el mapa no significa desbloqueo ni dominio. No se espera a cuatro misiones obligatorias.

Entre aplicaciones se mantiene variedad: una misión de palabras nueva realmente completada permite otra oportunidad preparada. El journal existente determina esa evidencia; repetir una misión, un registro editorial o un evento Arcade no la fabrica. Después de gramática se vuelve a palabras pendientes o termina el tramo, nunca se vacía una cola de quince variantes. Los IDs de paradas y completados se conservan; el ordinal del mapa puede cambiar al adelantar una parada. No se escriben migraciones ni progreso ficticio.

Pruebas: 41 enfocadas en recorrido, App y reanudación; integración 352/72 y build correctos. El caso de App utiliza hooks/I/O aislados, no una partida humana: PLAY → aplicación → HOTEL → BRUSH → aplicación → FAMILY → siguiente paquete, con Arcade existente y posición de Gramática separada. Cobertura de requisitos, recarga, no relleno, legacy IDs y no repetición como evidencia. No acredita diversión, audio escuchado, móvil o memoria diferida.

Cómo revisar: desde Inicio, completar normalmente un paquete de acción que tenga una parada gramatical publicada; al continuar, si sus palabras están practicadas, se ofrece su aplicación sin acumular otras tres misiones. Montar antes de escribir y rescate tras dos dificultades pertenecen a la entrega anterior y se mantienen. Tras la aplicación se continúa con palabras; salir y volver conserva la parada por ID. No reiniciar la cuenta ni cometer errores a propósito para probarlo.

Límites: no curso de 1000 palabras terminado, ni continuación contextual/conversación nueva, ni medios de borradores aprobados. El bundle principal conserva el aviso de tamaño (~500,63 kB minificado). Push y versión servida se registran por separado en el checkpoint del proyecto.
